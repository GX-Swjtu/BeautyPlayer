# v0.2 Windows 验证记录

日期：2026-09-28。环境：Windows 11 Pro 10.0.26200、Qt 6.11.2 MSVC x64、NVIDIA GeForce RTX 4070 Laptop GPU。保留输入尺寸；报告为本机实测，不代表 Android 性能。原始视频、PNG 与诊断日志在被 Git 忽略的 `artifacts/`、`test-media/` 中。

## 性能

4K 使用 Pexels 7477538 的 2160×3840、23.976 fps 原片；两种 v0.2 配置各播放 60 秒，统计第 5 秒以后的 fpsInterval 算术平均。旧版是此前同机、同素材全部特效的 30 秒记录，时长和执行时刻不同，仅作参考。

| 配置 | 平均输出 fps | 转换 ms | 检测+GPU+回读 ms | 两阶段合计 ms |
|---|---:|---:|---:|---:|
| v0.1 全部特效（历史基线） | 16.40 | 未分项 | 未分项 | 56.99 |
| v0.2 默认美颜 | 23.79 | 19.08 | 14.07 | 33.15 |
| v0.2 全部特效 | 23.80 | 22.50 | 29.86 | 52.35 |

并行阶段的合计耗时不等于输出帧间隔。全部特效单帧总成本变化较小，吞吐量约提升 45%，主要来自帧转换与 GPU 阶段重叠执行。默认配置不运行人脸检测。4K 每次循环/读片的短时掉帧仍存在：默认最低区间 22 fps，全部特效最低约 21.96 fps。不是保证每帧零丢帧。

Qt 开发日志显示 `Checking HW context: d3d11va`、`Using above hw context` 和硬件格式选择，确认 H.264 使用 D3D11VA；GL renderer 确认为 RTX 4070。保留 Qt 自动硬件选择，不强制不匹配的解码器。原图旁路直接交给输出 QVideoSink。

4K 默认测试采样私有内存约 1514–1776 MiB，结束 1589 MiB；全部特效约 1682–1944 MiB，结束 1747 MiB。仍有解码缓存、CPU/GPU 拷贝和多帧存储，不能将此方案称为移动端低内存零拷贝实现。

## 功能结果

- 通过：GPUPixel 单项美颜、当前帧回读、颜色、原尺寸、无脸清除；8 组帧旋转/镜像组合。
- 通过：默认强度有基础美颜且四项检测功能关闭；恢复推荐回到轻量预设。
- 通过：暂停修改参数立即刷新；原图对比与全参数归零画面匹配。
- 通过：真实 Qt 窗口事件触发美颜滑块、长按 3×、松手恢复原速、水平滑动后退、全屏切换。
- 通过：重新打开同一视频恢复到 3 秒附近；书签落盘后重读、媒体文件替换后失效、片尾清除、200 条上限及损坏 JSON 恢复。
- 通过：视频库大小写扩展名、重叠目录去重、搜索、子目录过滤、删除后刷新与扫描取消/重启。
- 通过：390×844 窄屏播放器、视频库和底部抽屉实机窗口渲染；这里的“实机”是 Windows 电脑，不是安卓设备。

视频库规模测试使用 100 个文件夹、10,000 个零字节 `.mp4` 索引夹具，只测目录枚举而非解码：工作线程约 **146 ms**，包含模型发布与测试等待约 **177 ms**；关键词查找返回 100 条。刚创建的本地 SSD 文件可能受系统缓存影响，不代表冷盘、网络盘或 Android，也未与 MX Player 作同条件比较。

## 未完成的边界

- 原分辨率 8 位 SDR 为当前范围；HDR、视频导出、多人脸、摄像头不在本次实现内。
- 仓库只发布源代码，未公开上传第三方 SDK、模型、视频或便携二进制。
